SLAM EXPLORER 0.4 - FRONT + REAR CAMERA UPDATE

Use REAR_CAMERA_SETUP.txt for the current update/install/preview commands.
The following 0.1 notes are historical; the old "not installed on Pi" statement
describes that original release, not the later Pi work in PI_VALIDATION.txt.
Camera update 0.4 has local validation only until installed and checked on Pi.

This is a separate ROS 2 package and web dashboard, not another patch to the
reactive obstacle page. It does not need another Nucleo firmware flash.
Uses your current Vehicle_Drive FW>=2, including the FW=7 diagnostic layout.
No code was installed or run on the Pi: SSH batch authentication failed.
Local tests use ROS stand-ins for drive logic; ROS nodes/plugins were not run.

WHAT IS IMPLEMENTED
- SLAM Toolbox asynchronous 2D mapping with scan matching and loop closure.
- robot_localization EKF: selected encoder longitudinal speed + zero lateral
  velocity for symmetric steering + BNO055 yaw. E2 is not required in default
  single-E1 mode. A zero/frozen E1 while driving stops the robot.
- map -> odom -> base_link -> laser/imu TF chain with one publisher per link.
- Nav2 Smac Hybrid-A* with measured counter-steer turning radius; forward-only
  Dubins paths, no spin-in-place or automatic blind-reverse recovery.
- Regulated Pure Pursuit path tracking, bounded speed PI output (0..50% duty).
  Configured minimum tracking/approach speed equals measured stable speed:
  this chassis reportedly needs about 50% duty to move. It is not assumed
  capable of precise creeping. Validate stopping distance and controller tuning.
- Path commitment: plan once, follow that path; only replan after tracking
  failure. Two bounded retries with a wait, then return failure to explorer.
- Automatic frontier exploration on reachable mapped free space. Goals stand
  back from unknown cells. Scoring balances frontier size and travel cost.
- Adaptive failure memory: failed areas get increasing retry cooldowns during
  this session. Active goals are not replaced on every scan/map update.
  This is map-based adaptation, not a neural network or permanent training.
- Local map/path/pose and camera dashboard, START/STOP, token link, port 8005.
- Short command/serial/scan/IMU/EKF/operator timeouts. Browser heartbeat loss
  stops drive and cancels exploration. Stops/faults need an explicit restart.
- Straight motion can leave rear-only obstacles behind the rear plane;
  turning keeps the full conservative envelope.

IMPORTANT LIMITS
Sensor fusion does not create missing encoder pulses. Single-E1 odometry is
an approximation: slip, tire geometry, encoder gearing and steering errors
still matter. IMU heading must have the right yaw sign/orientation; magnetic
interference can damage localization. No MCU source timestamp or CRC exists
on the text telemetry. Arrival time is used; this is not hardware time sync.
No camera depth/visual odometry is implemented. Camera is operator video.
The 12-inch-high LiDAR cannot see all low objects, drop-offs or overhangs.
The clearance/velocity loop and ROS integration are not physically validated.
CPU load/latency, ROS Lyrical plugin compatibility and closed-loop speed tuning
must be verified on the Pi before floor exploration.

3. MEASURE CALIBRATION (REQUIRED, NO INVENTED VALUES)
Edit ~/robot_nav_calibration.json. Template keeps verified=false and unknown
dimensions/scales null. Launch refuses unmeasured calibration even in passive
mode because guessed odometry would produce a misleading map.

You can measure encoder counts per metre directly without knowing gear ratio
or being able to rotate the locked shafts by hand:
- Stop all serial owners, place start/end marks on a clear straight floor.
- Check both configured forward commands physically move forward with wheels lifted.
- For a supervised powered test in clear space, run:
  cd ~/slam_explorer
  python3 measure_encoder.py --run-drive-test --seconds 3
- This explicitly runs both motors at -50% for 3 s, sends STOP, waits 2 s for
  coast, saves encoder_measurement.csv, then asks actual measured travel in m.
- It prints counts_per_meter and encoder_sign for each moving encoder.
- This output is an average scale, not a verified steady speed/stopping test.
  Include all coast distance; repeat over a known distance to check consistency.

Required values:
counts_per_meter: measured as above, or supply wheel_diameter_m and
  counts_per_wheel_rev (after gearing, quadrature x4).
encoder_index=1 by default; encoder_sign makes physical forward speed positive.
wheelbase_m: measured axle-center distance.
max_steer_rad: measured physical front angle at servo_travel_us. Rear must
  match the same magnitude in the opposite direction. Degrees*pi/180=radians.
servo_travel_us, front/rear centers/signs: measured steering calibration.
measured_speed_mps: measured steady forward speed at measured_duty_pct.
stopping_distance_m: conservative measured distance after zero command.
laser_frame: must exactly equal /scan header.frame_id (check ros2 topic echo).
laser_yaw_rad: initial pi radians matches your earlier 180-degree mount correction;
  VERIFY a known object ahead appears ahead in the map.
imu_yaw_sign: default -1 assumes BNO055 clockwise heading. Rotate the chassis
  left and confirm filtered yaw increases; correct sign before driving.
motor1_sign=motor2_sign=-1 now maps forward to negative PWM after the reverse test; verify physically.
Set verified=true only after these measurements and physical direction checks.

may mean mapping complete, insufficient visible free space, or a boxed-in
car-like chassis that cannot reach a new region without manual repositioning.
