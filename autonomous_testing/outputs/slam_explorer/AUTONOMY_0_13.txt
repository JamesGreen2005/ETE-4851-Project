SLAM EXPLORER 0.13 - AUTONOMY AND FUSION REWRITE
Built 2026-11-06. Software-tested release; NOT validated on this Pi or on grass.

CHANGES
- Three-stage steering-lattice viewpoint search with forward/reverse segments,
  one direction change, heading diversity, and revisitation penalties.
- Collision checks cover every grid cell intersecting the conservative body
  disk along each arc. Unknown cells never authorize body movement.
- Information gain uses rays stopped by occupied cells, rather than counting
  unknown cells behind obstacles. Nav2 Reeds-Shepp still plans/validates the
  actual route to each selected viewpoint; candidate segments are proposals.
- Visited odometry points are transformed into the current map frame before
  scoring, including after map-to-odom corrections.
- Existing robot_localization EXTENDED KALMAN FILTER now accepts independent
  LiDAR and optional camera body-frame velocity observations in addition to
  IMU heading and encoder longitudinal speed / lateral constraint.
- Scan-to-scan trimmed ICP uses calibrated LiDAR mounting. Frame age, overlap,
  residual, geometry, interval and motion outlier checks reject bad estimates.
  No SLAM map pose is fed back into the odom EKF; SLAM owns map->odom and EKF
  owns odom->base_link. The scan prior and map still share LiDAR information;
  they are not statistically independent, and covariance floors are provisional.
- Camera odometry uses tracked ground features, forward/backward optical-flow
  checks, metric ground homography, RANSAC consensus and rigid-motion checks.
  Each camera requires measured intrinsics and a verified ground calibration.
  BOTH camera odometry sources are DISABLED by default, as requested. Video
  remains available. No depth, object recognition or obstacle-free terrain
  certification is inferred from video. Slopes, suspension changes, moving
  grass and nonplanar surfaces can invalidate this planar model.
- Both motor currents affect ENCODER MEASUREMENT CONFIDENCE, not position.
  Missing/offline readings reduce confidence. Imbalanced current and load above
  an optional measured reference increase wheel covariance. Current does not
  prove slip or establish torque without a motor/load model.
- A second encoder can participate only with its own measured scale and sign.
  Encoder disagreement increases wheel covariance. Existing primary-encoder
  stale/no-motion stops remain. No second scale or direction is guessed.
- MAXIMUM MOTOR DUTY IS NOW 100%, configurable by max_duty_pct. Motor protocol
  and the existing Vehicle_Drive firmware source already support +/-100%.
  No new firmware is included or flashed by this package.
- Navigation still requests measured_speed_mps. 100% DUTY IS A CEILING, NOT A
  FORCED CONSTANT OUTPUT OR A CLAIM THAT THE VEHICLE SPEED HAS DOUBLED. At the
  existing speed target, the controller may use less than 100% duty. To request
  a faster cruising speed, measure steady speed and stopping distance at that
  operating point, then update measured_speed_mps, measured_duty_pct and
  stopping_distance_m together. Do not relabel old 50% measurements as 100%.
- Swept braking reach scales with the largest requested/encoder/EKF speed and
  quadratically scales the measured stopping-distance baseline. This is a
  conservative software model, not a measured grass braking profile.
- Dashboard identifies SLAM-EXPLORER-0.13 and displays fusion health, source
  rejection reasons, motor ceiling and wheel confidence in its status panel.

OPTIONAL CALIBRATION KEYS IN ~/robot_nav_calibration.json
max_duty_pct: defaults to 100 if absent; valid 1..100.
load_reference_current_a: null/absent until a normal-load current is measured.
secondary_encoder: null/absent until separately calibrated. For example the
schema is {"index":2,"sign":MEASURED_SIGN,"counts_per_meter":MEASURED_SCALE}.
It must select the other encoder, never the same as encoder_index.
front_odometry_calibration / rear_odometry_calibration: null/absent until ready;
otherwise each is an absolute Pi path to a JSON camera calibration file.
Required camera file fields:
  verified: true ONLY after measured calibration and a scale/direction test
  width, height: native camera image dimensions
  camera_matrix: measured 3x3 intrinsics K
  distortion: measured OpenCV distortion coefficients
  ground_homography: measured 3x3 map from UNDISTORTED pixels (P=K) to ground
                     coordinates in base_link, metres, x forward and y left
  ground_roi: polygon [[pixel_x,pixel_y],...] in original image pixels selecting
              only visible ground, excluding the robot, sky and non-ground objects
Keep camera USB ports, image sizes and mounts fixed. Validate metric movement
in each direction before enabling camera observations. The two cameras are
not assumed to be stereo. This release does not perform camera calibration.
